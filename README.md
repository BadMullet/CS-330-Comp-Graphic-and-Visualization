# CS-330 Comp Graphic and Visualization


**How do I approach designing software?**

This project helped me understand that designing software works better when I break a larger project into smaller parts instead of trying to complete everything at once. For my 3D scene, I started by looking at the reference image and deciding which basic shapes could be used to recreate the objects. I then worked through the scene one part at a time, including the shapes, transformations, textures, camera controls, and lighting. This made it easier to find problems and make changes without affecting the entire scene.

One design skill I improved was learning how to take a real object and break it down into simpler 3D shapes. For example, some objects needed more than one shape and several transformations before they looked right. I also learned that the first design does not always need to be the final design. I made changes to the size, position, rotation, textures, and lighting as the project developed. I could use this same approach in future projects by planning the main parts first, building them separately, and then combining and adjusting them as needed.

**How do I approach developing programs?**

One of the biggest development strategies I used during this project was working in small steps and testing my code often. Instead of adding several changes at the same time, I would add something, run the program, and see how it affected the scene. This was especially helpful when working with object placement, camera movement, textures, and lighting because even a small change in the code could make a noticeable difference.

Iteration was a major part of developing my scene. Many parts of the project needed several adjustments before they looked or worked the way I wanted. For example, I changed object sizes and positions, adjusted textures, worked on the camera controls, and changed the lighting until the scene looked more natural. My approach to coding also changed throughout the milestones. At the beginning, I was mostly focused on getting each individual requirement to work. As I progressed, I became better at understanding how the different parts of the program worked together. By the final project, I was more comfortable making changes, testing them, and fixing problems without having to change large sections of code.

**How can computer science help me in reaching my goals?**

Computational graphics and visualization gave me experience with an area of computer science that I had not worked with very much before. I learned more about 3D coordinates, transformations, textures, lighting, cameras, and how code can be used to create and control a visual scene. Even though graphics is not the main area I plan to pursue, these skills still help me understand how different parts of software work together and how changes in code affect what the user sees.

For my future education, this course gave me more experience solving problems, testing code, and working through a larger project over several milestones. Those are skills I can use in other computer science courses. Professionally, I am more interested in cybersecurity, but the programming and troubleshooting skills from this course can still be useful. Cybersecurity also requires understanding how software works, finding problems, testing solutions, and paying attention to details. This project gave me more practice with those skills while also giving me experience with a different area of computer science.
